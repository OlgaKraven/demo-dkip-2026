Соберём настольное приложение «Молочный комбинат „Полесье“». Создадим формы в визуальном конструкторе, подключим обработчики кнопок и проследим путь от «Войти» до запроса в базу. Рядом с шагами показаны работающие окна.

1. Создайте свой проект

До работы с кодом выпишите из задания окна и действия: вход с пазлом, просмотр данных, управление пользователями для администратора. Разделите работу на две формы: LoginForm для входа и MainForm для вкладок. Сначала соберите внешний вид, затем подключайте действия.

  1. Запустите Visual Studio → «Создать проект». В поиске шаблонов введите Windows Forms. Выберите «Приложение Windows Forms (.NET Framework)», язык C#.
  2. Название проекта — Polesie; расположение — ваша рабочая папка; платформа — .NET Framework 4.8. Нажмите «Создать». Если шаблона нет, в Visual Studio Installer нужен компонент «Разработка классических приложений .NET».
  3. В «Обозревателе решений» найдите Form1.cs. Нажмите F2, введите LoginForm.cs и согласитесь переименовать класс. Откройте Program.cs: в Main должна быть строка Application.Run(new LoginForm());.
  4. Нажмите F5. Должно открыться пустое окно. Закройте его или нажмите Shift+F5, прежде чем редактировать конструктор.
  5. Правой кнопкой по проекту → «Добавить» → «Форма Windows Forms». Имя — MainForm.cs. Нажмите «Добавить». Создавать второй проект для второй формы не требуется.

Сохраните решение. Сначала выполните раскладку форм ниже. Готовый проект внизу страницы используйте для сравнения свойств и кода после собственной попытки.

При подключении базы установите через «Проект → Управление пакетами NuGet» пакет MySqlConnector 2.4.0. В «Проект → Свойства → Сборка → Символы условной компиляции» добавьте MYSQL: общий Db.cs выберет MySqlConnection. Базу создавайте через phpMyAdmin.

При подключении базы установите через «Проект → Управление пакетами NuGet» пакет Npgsql 4.1.14. В «Проект → Свойства → Сборка → Символы условной компиляции» добавьте POSTGRESQL: так общий Db.cs выберет NpgsqlConnection.

Формы LoginForm и MainForm уже созданы; не добавляйте их повторно. Все классы в этом разборе используют пространство имён Polesie.

3. Соберите форму в конструкторе Visual Studio

В обозревателе решений найдите файл формы в своём проекте (в готовом примере — в папке UI). Нажмите правой кнопкой LoginForm.cs → «Просмотреть конструктор» или Shift+F7. Чтобы перейти к обработчикам, нажмите F7. Раскладка хранится в LoginForm.Designer.cs, действия — в LoginForm.cs. Это две части одного класса.

Откройте инструменты конструктора

  1. В своём проекте нажмите правой кнопкой LoginForm.cs → «Просмотреть конструктор» (Shift+F7). Должна появиться пустая поверхность окна с точками или сеткой.
  2. Откройте «Вид → Панель элементов» (Ctrl+Alt+X). Раскройте «Все формы Windows Forms». В поиске панели вводите английское имя элемента: Label, TextBox, Button.
  3. Откройте «Вид → Окно свойств» (F4). Щёлкните фон формы: вверху окна свойств должен быть выбран LoginForm. Для удобства включите сортировку по алфавиту.
  4. Измените Text, Size, MinimumSize и StartPosition по таблице. Чтобы изменить составное свойство Size, раскройте «+» и отдельно задайте Width и Height.

Разместите первый элемент: поле логина

  1. В панели элементов найдите FlowLayoutPanel и перетащите на пустую форму. В F4 задайте (Name) = layout. Откройте список Dock и выберите центральный прямоугольник Fill: панель займёт окно.
  2. У панели задайте FlowDirection = TopDown, WrapContents = False, Padding = 28, AutoScroll = True. Она будет сама располагать элементы вертикально.
  3. Перетащите Label внутрь панели. В F4 задайте (Name) = titleLabel, Text = Молочный комбинат «Полесье», AutoSize = True. У Font нажмите «…», выберите Segoe UI, размер 20, полужирный.
  4. По аналогии добавьте ещё один Label: (Name) = loginLabel, Text = Логин. Затем перетащите TextBox внутрь той же панели, под метку.
  5. Выберите TextBox и задайте (Name) = login, Width = 300, MaxLength = 64. Text оставьте пустым: это место для ввода пользователем.
  6. Если элементы оказались не в том порядке, откройте «Вид → Другие окна → Структура документа». В дереве внутри layout переместите titleLabel, loginLabel, login в указанном порядке.
  7. Нажмите F5: в окне должны быть заголовок, метка и поле, в которое можно печатать. Остановите запуск перед продолжением.

Добавьте остальные элементы по аналогии

Привяжите кнопку к коду входа

  1. Выберите кнопку enter. В F4 нажмите значок молнии — это список событий.
  2. У события Click укажите SignIn. В готовом проекте этот метод уже существует.

  4. В конструкторе класса оставьте InitializeComponent(); первым. После него добавьте пазл в подготовленную панель:
public LoginForm()
{
    InitializeComponent();

    puzzleHost.Controls.Add(puzzle);

Поле private readonly PuzzleControl puzzle; объявлено внутри класса, перед конструктором. Во время запуска панель заполняется картинкой и фрагментами. Картинки должны лежать в Assets рядом с exe. В визуальном конструкторе достаточно разместить саму панель.

Подготовьте первую учётную запись

Для первого запуска нужен администратор в users. Пароль должен быть сохранён в формате, который проверяет ваш код. Если используете Passwords из разбора, обычный текст в password_hash не подойдёт.

  1. После добавления класса Passwords и успешной сборки поставьте точку останова F9 на Application.Run в Program.cs и запустите F5.
  2. Откройте «Отладка → Окна → Интерпретация» (Immediate). Введите ? Polesie.Passwords.Hash("ВашУчебныйПароль!2026"). Скопируйте полученную строку salt:hash без внешних кавычек.
  3. В SQL своей базы вставьте одну запись, подставив полученную строку вместо ВАШ_ХЭШ:
INSERT INTO users
(login, password_hash, role, failed_attempts, is_locked)
VALUES ('admin', 'ВАШ_ХЭШ', 'admin', 0, FALSE);

Не выполняйте вставку повторно для уже существующего admin. Остановите отладку, снимите точку останова и запустите приложение заново. Для входа вводите исходный учебный пароль, а не хэш.

7. Разберите обработчик кнопки

  1. enter.Click += SignIn связывает щелчок с методом SignIn. До щелчка проверка не выполняется.
  2. login.Text и password.Text содержат введённые строки.
  3. puzzle.IsSolved() возвращает true или false, а не готовое сообщение.
  4. AuthService проверяет запись и возвращает объект User при успехе. Объект переносит id, login и role в главное окно.
  5. Hide() скрывает окно входа. ShowDialog() открывает рабочее окно. Когда его закрывают, finally очищает пароль, перемешивает пазл и снова показывает вход.
  6. catch отображает ожидаемые ошибки понятным сообщением. Ошибка связи с сервером не закрывает программу.

9. Разберите три неудачные попытки

SignIn сначала требует заполнить поля. Затем ищет логин и проверяет is_locked. Только существующему незаблокированному пользователю засчитывается неудачная попытка. Неверный пароль или неверный пазл дают ровно одну ошибку на нажатие «Войти»; обе ошибки вместе не считаются двумя.

Событиеfailed_attemptsis_locked
Новая запись0false
Неверный пароль1false
Неверный пазл2false
Ещё одна ошибка3true
Верный пароль после блокировки3true, вход запрещён
Администратор снял блокировку0false

Успешный вход до третьей ошибки сбрасывает счётчик в 0. Поэтому две ошибки, затем успех, затем ещё ошибка — это одна новая ошибка, а не блокировка. Для неизвестного логина нет учётной записи, которую можно заблокировать; возвращается общее сообщение об ошибке.

Транзакция объединяет чтение пользователя и обновление счётчика. FOR UPDATE блокирует эту запись до завершения транзакции, чтобы два одновременно открытых окна не потеряли одну из попыток. Commit() выполняется до сообщения об ошибке: увеличение счётчика должно сохраниться даже при отказе во входе.

10. Посмотрите, что хранится вместо пароля

Поле password_hash содержит соль и результат PBKDF2, разделённые двоеточием. Соль — случайные 16 байт. Метод Hash вычисляет значение при создании или замене пароля. Метод Verify повторяет вычисление с сохранённой солью и сравнивает байты. Из таблицы не читается пароль в открытом виде.

Для двух учебных учётных записей в 03-demo.sql уже записаны готовые значения. Подставлять текст admin в password_hash нельзя. При вводе новых пользователей хэш создаётся автоматически. Сам пароль не следует применять с Trim: пробел может быть его частью.

14. Проверьте приложение перед сохранением

  • Оба пустых поля → просьба заполнить логин и пароль.
  • Верный пароль и неверный пазл → отказ; счётчик увеличен на один.
  • Верный пазл и неверный пароль → точное сообщение из задания.
  • Третья последовательная ошибка → блокировка; перезапуск приложения её не снимает.
  • Снятие блокировки администратором → успешный вход после правильного пазла.
  • Роль user → нет вкладки управления пользователями.
  • Изменение размеров → таблица растёт, подписи и поля не исчезают.
