Соберём настольное приложение «Молочный комбинат „Полесье“». Начнём с запуска готового проекта, затем проследим путь от кнопки «Войти» до запроса в базу и разберём каждый файл.

1. Подготовьте Visual Studio

Нужна Visual Studio с компонентом «Разработка классических приложений .NET» и .NET Framework 4.8. В проекте используются обычные Windows Forms, обработчики кнопок и SQL-команды. NuGet восстанавливает драйвер базы и необходимые библиотеки при первой сборке; на рабочем месте без сети подготовьте их заранее.

Скачайте ZIP выбранного стека и распакуйте целиком. Не открывайте csproj внутри архива. Откройте examples/{{stack}}/Polesie.csproj двойным щелчком. Соседняя папка shared должна остаться на месте: в ней общие формы и классы.

В этом проекте установлен MySqlConnector 2.4.0. Он создаёт MySqlConnection. Сервер — MySQL 8.0.16+; клиент базы может быть Workbench или phpMyAdmin.

В этом проекте установлен Npgsql 4.1.14, совместимый с .NET Framework 4.8. Он создаёт NpgsqlConnection. SQL выполняется в базе PostgreSQL; не устанавливайте вместо него драйвер MySQL.

  2. В папке проекта появится bin/Debug. Там лежат exe, библиотеки, Assets и Sql.
  3. Скопируйте connection.example.txt в этой папке под именем connection.local.txt. Проверьте, что Проводник показывает расширения и файл не назван connection.local.txt.txt.

  5. Убедитесь, что скрипты 01-schema.sql, 02-customers.sql и 03-demo.sql уже выполнены. Нажмите F5.

3. Выполните первый вход

Введите admin и DemoAdmin!2026. Посмотрите на изображение слева. Справа нажмите сначала один фрагмент, затем другой — они поменяются местами. Повторяйте, пока справа не получится тот же рисунок. Только после этого нажмите «Войти».

Появится сообщение «Вы успешно авторизовались», затем окно со вкладками. Учётная запись user / DemoUser!2026 открывает только заказчиков и стоимость. Вкладка пользователей доступна администратору.

6. Разберите обработчик кнопки

  1. enter.Click += SignIn связывает щелчок с методом SignIn. До щелчка проверка не выполняется.
  2. login.Text и password.Text содержат введённые строки.
  3. puzzle.IsSolved() возвращает true или false, а не готовое сообщение.
  4. AuthService проверяет запись и возвращает объект User при успехе. Объект переносит id, login и role в главное окно.
  5. Hide() скрывает окно входа. ShowDialog() открывает рабочее окно. Когда его закрывают, finally очищает пароль, перемешивает пазл и снова показывает вход.
  6. catch отображает ожидаемые ошибки понятным сообщением. Ошибка связи с сервером не закрывает программу.

8. Проследите подключение к базе

Db.Open() читает настройки и открывает соединение. using закрывает соединение и освобождает ресурсы даже при ошибке. Разница двух сборок находится внутри #if MYSQL: компилятор включает MySqlConnection в MySQL-проекте и NpgsqlConnection в PostgreSQL-проекте.

Метод Command получает текст SQL и значения. Значения превращаются в параметры @p0, @p1 и так далее. Если логин содержит апостроф, он остаётся данными и не становится частью SQL-команды.

9. Разберите три неудачные попытки

SignIn сначала требует заполнить поля. Затем ищет логин и проверяет is_locked. Только существующему незаблокированному пользователю засчитывается неудачная попытка. Неверный пароль или неверный пазл дают ровно одну ошибку на нажатие «Войти»; обе ошибки вместе не считаются двумя.

Событиеfailed_attemptsis_locked
Новая запись0false
Неверный пароль1false
Неверный пазл2false
Ещё одна ошибка3true
Верный пароль после блокировки3true, вход запрещён
Администратор снял блокировку0false

Успешный вход до третьей ошибки сбрасывает счётчик в 0. Поэтому две ошибки, затем успех, затем ещё ошибка — это одна новая ошибка, а не блокировка. Для неизвестного логина нет учётной записи, которую можно заблокировать; возвращается общее сообщение об ошибке.

Транзакция объединяет чтение пользователя и обновление счётчика. FOR UPDATE блокирует эту запись до завершения транзакции, чтобы два одновременно открытых окна не потеряли одну из попыток. Commit() выполняется до сообщения об ошибке: увеличение счётчика должно сохраниться даже при отказе во входе.

10. Посмотрите, что хранится вместо пароля

Поле password_hash содержит соль и результат PBKDF2, разделённые двоеточием. Соль — случайные 16 байт. Метод Hash вычисляет значение при создании или замене пароля. Метод Verify повторяет вычисление с сохранённой солью и сравнивает байты. Из таблицы не читается пароль в открытом виде.

Для двух учебных учётных записей в 03-demo.sql уже записаны готовые значения. Подставлять текст admin в password_hash нельзя. При вводе новых пользователей хэш создаётся автоматически. Сам пароль не следует применять с Trim: пробел может быть его частью.

11. Добавьте и измените пользователя

  1. Войдите как admin. Откройте вкладку «Пользователи».
  2. Нажмите «Новый пользователь», введите логин student, пароль и роль user. Нажмите «Сохранить».
  3. Повторите добавление с тем же логином. Программа должна сообщить, что пользователь уже существует.
  4. Нажмите строку student. Смените логин на student2. Оставьте пароль пустым и сохраните: прежний пароль продолжит работать.
  5. Выберите эту строку ещё раз и введите новый пароль. После сохранения старый пароль больше не подходит.
  6. Заблокируйте student2 тремя ошибками при входе. Вернитесь под admin, выберите строку, отметьте «Снять блокировку» и сохраните. Проверяйте одновременно is_locked=false и failed_attempts=0.

Users.Save проверяет права по записи в базе, а не только по видимости кнопки. Логины приводятся к нижнему регистру и очищаются от пробелов по краям; Admin и admin обозначают одну запись. Ограничение UNIQUE остаётся последней защитой от дублей, если два окна сохраняют одновременно.

14. Проверьте приложение перед сохранением

  • Оба пустых поля → просьба заполнить логин и пароль.
  • Верный пароль и неверный пазл → отказ; счётчик увеличен на один.
  • Верный пазл и неверный пароль → точное сообщение из задания.
  • Третья последовательная ошибка → блокировка; перезапуск приложения её не снимает.
  • Снятие блокировки администратором → успешный вход после правильного пазла.
  • Роль user → нет вкладки управления пользователями.
  • Изменение размеров → таблица растёт, подписи и поля не исчезают.
  • Недоступный сервер → сообщение о соединении, приложение остаётся открытым.
