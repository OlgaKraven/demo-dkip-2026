3. Прочитайте одну таблицу построчно

CREATE TABLE counterparty создаёт таблицу. Столбец id VARCHAR(32) PRIMARY KEY хранит текстовый идентификатор длиной до 32 символов; PRIMARY KEY запрещает повтор и пустое значение. name VARCHAR(255) NOT NULL требует имя. Поля inn, address, phone текстовые: знак «+», ведущие нули и буквы должны сохраниться.

DECIMAL(12,3) хранит точное количество с тремя знаками после запятой. Для денег используем DECIMAL(12,2). FLOAT не подходит, если требуется точное округление денежных результатов. CHECK(qty>0) запрещает отрицательное и нулевое количество, а FOREIGN KEY запрещает ссылку на несуществующий объект.

AUTO_INCREMENT автоматически выдаёт новый числовой идентификатор. В MySQL 8 ограничения CHECK исполняются начиная с 8.0.16. BOOLEAN — логический тип, представляемый сервером числом 0/1. В проекте параметр C# передаёт именно bool.

GENERATED BY DEFAULT AS IDENTITY автоматически выдаёт идентификатор. После учебной вставки явных id файл 03-demo.sql передвигает счётчики через setval, чтобы следующая новая запись не попыталась занять уже использованный номер. BOOLEAN хранит TRUE/FALSE.

Дополнительный способ: импорт JSON через C#-приложение

Этот способ можно выполнить после создания приложения в модуле 4. Основной маршрут работы с базой выше использует средства СУБД.

Значения id и name не должны быть пустыми, идентификаторы в файле не должны повторяться. Текстовые поля содержат текст или null, признаки — true или false без кавычек. У первой записи id 000000001, телефон начинается с «+», адрес содержит город. Пустой ИНН остаётся пустым текстом. Для дополнительного импорта через приложение проверьте: повторный импорт не добавляет дубли; некорректный файл не оставляет часть записей; при недоступном сервере появляется сообщение о соединении, а окно приложения остаётся открытым.

7. Подготовьте данные для проверки запроса

Чтобы проверить следующий модуль, в собственной базе нужны продукция, материалы, состав, цены и хотя бы один заказ. Используйте реквизиты исходных документов; для отдельной учебной проверки можно задать свой небольшой набор и заранее посчитать его вручную.

  1. Добавьте материалы и продукцию в справочник item. Запишите присвоенные id: они понадобятся для ссылок.
  2. Создайте specification для выбранной продукции и укажите output_qty — количество продукции, на которое рассчитаны нормы. В specification_material добавьте по одной строке на каждый материал, с его id и нормой.
  3. Для каждого материала добавьте price: id материала, дату начала действия цены и amount. На дату заказа должна существовать подходящая цена.
  4. Создайте шапку customer_order: номер, дату и ссылки на реально существующих контрагентов. Затем добавьте позиции customer_order_line с id заказа, id продукции, количеством и ценой продажи.
  5. Проверьте связи и вручную вычислите материальную стоимость. Готовый набор с контрольными суммами вынесен в отдельный раздел.

Через интерфейс: выберите таблицу → Вставить → заполните поля → Вперёд. Автоматический числовой id оставьте пустым. После сохранения откройте Обзор и запишите полученный номер. Остальные таблицы заполните по аналогии, заменяя поля по своей структуре.

Через интерфейс: правой кнопкой по таблице → View/Edit Data → All Rows. В строке добавления заполните поля, оставив автоматически выдаваемый id незаданным; сохраните изменения кнопкой Save Data. Обновите результат и запишите выданный id. Остальные таблицы заполните по аналогии. Если таблица не редактируется, проверьте наличие первичного ключа.

Через код: составьте INSERT по образцу импорта заказчиков, заменив имя таблицы, список столбцов и значения. Автоматический id не включайте в список. Внешние ключи берите из уже сохранённых родительских записей.

8. Проверьте ограничения и сохраните результат

Попробуйте добавить строку заказа с несуществующим номером заказа — сервер должен отклонить её по FK. Попытку сделайте в отдельной транзакции и отмените. Для проверки UNIQUE попробуйте повторить существующий login: повтор должен быть запрещён. Не отключайте ограничения, чтобы «пропустить» ошибку; исправляйте ссылку или значение.

В phpMyAdmin выберите базу → «Экспорт» → «Обычный» (Custom) → все 11 таблиц → формат SQL → структура и данные → «Вперёд». Сохраните файл. Проверьте, что в нём есть CREATE TABLE и INSERT. Для проверки создайте другую пустую базу и загрузите файл через «Импорт».

В pgAdmin нажмите правой кнопкой по базе → Backup → Format: Plain. Сохраните SQL со структурой и данными. Для проверки восстановления создайте другую пустую базу и выполните SQL в ней. Не направляйте пробное восстановление в рабочую базу.

Результат: база с 11 таблицами, внешними ключами и шестью исходными заказчиками. Скрипты лежат в Sql; дамп — отдельный файл. Для модуля 3 откройте 04-cost.sql.

9. Сохраните результат в папку сдачи

SQL со структурой и данными или дамп в требуемом формате. Созданная база на сервере сама по себе не является файлом сдачи: сделайте экспорт и проверьте восстановление в другой пустой базе.

Используйте выделенную папку на рабочем столе. При онлайн-сдаче загрузите итоговые файлы в хранилище, организованное для экзамена, и проверьте загрузку.
