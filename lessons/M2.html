1. Создайте пустую базу

  3. Нажмите имя новой базы слева. Дальше работайте внутри неё.
  1. В pgAdmin подключитесь к серверу. Правой кнопкой по Databases → Create → Database.
  2. Введите rassvet_demo_2026 → Save. Откройте Schemas → public.

TINYINT(1) хранит 0 или 1: нет или да. NULL разрешает отсутствие значения. A_I автоматически выдаёт числовой номер; для текстового id он не нужен.

  1. Откройте public → Tables → Create → Table. Name = counterparty.
  2. На вкладке Columns кнопкой «+» добавьте семь полей. Используйте настройки из карточки counterparty в следующем шаге. VARCHAR — character varying, длину введите отдельно; BOOLEAN — boolean.
  3. У id и name включите Not NULL. У is_salesman и is_buyer — Not NULL и Default value = false. Для inn, address и phone отсутствие значения разрешено.
  4. Constraints → Primary Key → «+» → Columns = id. Identity не включайте. Сверьте SQL и нажмите Save.

Проверьте: В counterparty семь полей, id — первичный ключ. Телефон и ИНН имеют текстовый тип.

5. Свяжите заказ с заказчиком

  1. Откройте customer_order → «Структура» → «Связи».
  2. Внешний ключ: столбец customer_id → ваша база → counterparty → id. ON DELETE и ON UPDATE = RESTRICT. Сохраните.
  3. Повторите для executor_id → counterparty.id, затем для остальных связей из карточек.
  1. Откройте Properties таблицы customer_order → Constraints → Foreign Key → «+».
  2. На Columns задайте Local column = customer_id, References = public.counterparty, Referencing = id. Сохраните.
  3. Повторите для executor_id и остальных внешних ключей из карточек.

Один заказчик — много заказов: 1 : N. Ссылка хранится на стороне «много», в customer_order.customer_id. Типы связанного поля и ключа должны совпадать.

Проверьте: В свойствах customer_order есть два внешних ключа на counterparty.id. Похожих имён полей недостаточно — сохраните ограничения.

6. Задайте допустимые значения

  1. У users.login добавьте UNIQUE: два пользователя с одинаковым логином недопустимы.
  2. Перенесите CHECK из карточек. Например, количество в строке заказа должно быть больше нуля.
  3. Если редактор вашей версии не показывает CHECK, добавьте ограничение на вкладке SQL командой ниже. Повторять существующее ограничение не нужно.
ALTER TABLE customer_order_line
ADD CONSTRAINT chk_order_qty CHECK (qty > 0);

При ошибке связи проверьте типы полей, первичный ключ у родителя и существование указанной записи. В MySQL таблицы должны использовать InnoDB.

Проверьте: Схема содержит PRIMARY KEY, FOREIGN KEY, UNIQUE и проверки значений, указанные в карточках.
