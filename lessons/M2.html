Теперь превратим диаграмму в действующую базу. Выберите MySQL или PostgreSQL выше: названия таблиц сохраняются, меняются подключение и отдельные SQL-конструкции.

1. Подготовьте сервер и пустую базу

Откройте MySQL Workbench. Создайте подключение к своему серверу: Hostname 127.0.0.1, Port 3306, Username — пользователь, выданный на рабочем месте. Нажмите Test Connection. Пароль сервера не совпадает с паролем администратора учебного приложения.

Создайте схему rassvet_demo_2026, выберите кодировку utf8mb4. После создания дважды нажмите имя схемы слева, чтобы она стала текущей. В phpMyAdmin: «Базы данных» → имя → utf8mb4 → «Создать» → вкладка SQL. Оба интерфейса отправляют команды серверу.

CREATE DATABASE rassvet_demo_2026 CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;
USE rassvet_demo_2026;

Откройте pgAdmin. Разверните Servers и подключитесь своим пользователем. Правой кнопкой на Databases → Create → Database. Назовите базу rassvet_demo_2026. Затем выделите именно её и откройте Query Tool. Команду CREATE DATABASE выполняют вне транзакции и отдельно от остальных файлов.

CREATE DATABASE rassvet_demo_2026;
-- После создания подключитесь к этой базе.
-- Таблицы примера находятся в стандартной схеме public.

3. Прочитайте одну таблицу построчно

CREATE TABLE counterparty создаёт таблицу. Столбец id VARCHAR(32) PRIMARY KEY хранит текстовый идентификатор длиной до 32 символов; PRIMARY KEY запрещает повтор и пустое значение. name VARCHAR(255) NOT NULL требует имя. Поля inn, address, phone текстовые: знак «+», ведущие нули и буквы должны сохраниться.

DECIMAL(12,3) хранит точное количество с тремя знаками после запятой. Для денег используем DECIMAL(12,2). FLOAT не подходит, если требуется точное округление денежных результатов. CHECK(qty>0) запрещает отрицательное и нулевое количество, а FOREIGN KEY запрещает ссылку на несуществующий объект.

AUTO_INCREMENT автоматически выдаёт новый числовой идентификатор. В MySQL 8 ограничения CHECK исполняются начиная с 8.0.16. BOOLEAN — логический тип, представляемый сервером числом 0/1. В проекте параметр C# передаёт именно bool.

GENERATED BY DEFAULT AS IDENTITY автоматически выдаёт идентификатор. После учебной вставки явных id файл 03-demo.sql передвигает счётчики через setval, чтобы следующая новая запись не попыталась занять уже использованный номер. BOOLEAN хранит TRUE/FALSE.

6. Проверьте импорт

SELECT COUNT(*) FROM counterparty;
SELECT id,name,inn,address,phone,is_salesman,is_buyer
FROM counterparty ORDER BY id;

Ожидается 6 записей. У первой записи id 000000001, телефон начинается с «+», адрес содержит город. Пустой ИНН остаётся пустым текстом. Значения вроде 2147483647 вместо телефона означают, что выбран неправильный числовой тип.

8. Проверьте ограничения и сохраните результат

Попробуйте добавить строку заказа с несуществующим номером заказа — сервер должен отклонить её по FK. Попытку сделайте в отдельной транзакции и отмените. Для проверки UNIQUE попробуйте повторить существующий login: повтор должен быть запрещён. Не отключайте ограничения, чтобы «пропустить» ошибку; исправляйте ссылку или значение.

Для резервной копии в Workbench откройте Server → Data Export, выберите свою схему и структуру с данными, затем Export to Self-Contained File. В phpMyAdmin откройте базу → «Экспорт» → SQL. Проверьте, что в файле есть CREATE TABLE и INSERT.

В pgAdmin нажмите правой кнопкой по базе → Backup → Format: Plain. Сохраните SQL со структурой и данными. Для проверки восстановления создайте другую пустую базу и выполните SQL в ней. Не направляйте пробное восстановление в рабочую базу.
