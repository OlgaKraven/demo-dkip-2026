Учебный пример проектной документации

Назначение и состав системы

Приложение предназначено для авторизации сотрудников, просмотра контрагентов, расчёта материальной стоимости заказов и управления учётными записями. Реализация: C# Windows Forms + {{stackLabel}}, .NET Framework 4.8.

Роль user предоставляет просмотр контрагентов и стоимости. Роль admin дополнительно предоставляет добавление и изменение пользователей, сброс блокировки и импорт JSON. Пользовательские файлы остаются на рабочем компьютере.

Установка и запуск

  1. Создать пустую базу rassvet_demo_2026 на сервере {{stackLabel}}.
  2. Выполнить скрипты 01-schema.sql, 02-customers.sql, 03-demo.sql в указанном порядке.
  3. Открыть examples/{{stack}}/Polesie.csproj в Visual Studio. Восстановить NuGet-пакеты, собрать проект.
  4. В Data/Db.cs изменить ConnectionString: адрес, порт, база, пользователь и пароль сервера. Сохранить исходник и снова собрать проект.
  5. Запустить Polesie.{{stack}}.exe. Сохранить рядом с программой папки Assets, Sql и DLL из результата сборки.

Учебные учётные записи: admin / DemoAdmin!2026 и user / DemoUser!2026. В базе содержатся PBKDF2-хэши. Для новых пользователей хэш формируется при сохранении. Реквизиты базы в Db.cs не являются реквизитами этих учётных записей.

Структура и данные

UI — формы LoginForm, MainForm и компонент PuzzleControl. Models — отдельные классы User, Counterparty, Item, Price, Specification, SpecificationMaterial, CustomerOrder, CustomerOrderLine, Production, ProductionProduct и ProductionMaterial. Data/Db.cs — открытие соединений, параметризованные команды, выборки Table, подсчёт Count и изменения Execute. Services — AuthService, Passwords, Users, ImportCustomers.

База содержит 11 таблиц: counterparty, item, price, specification, specification_material, customer_order, customer_order_line, production, production_product, production_material, users. Идентификаторы, адреса, телефоны и ИНН из JSON хранятся текстом. Количества и деньги используют DECIMAL. Связи реализованы внешними ключами.

Вход и управление доступом

Сотрудник вводит логин и пароль и собирает пазл обменом двух фрагментов. Для правильного порядка IsSolved возвращает true. При нажатии «Войти» проверяется существующий пользователь, состояние блокировки, пароль и пазл. Успех возвращает User и обнуляет счётчик ошибок.

Неверный пароль или пазл увеличивают failed_attempts на один. После третьей последовательной ошибки устанавливается is_locked=true. Состояние хранится в базе и сохраняется при закрытии программы. Для неизвестного логина возвращается сообщение об ошибке без создания новой записи.

Работа пользователя

После входа открываются вкладки «Заказчики» и «Стоимость заказов». Таблицы доступны для чтения. Закрытие рабочего окна возвращает к форме входа, очищает пароль и перемешивает пазл.

Запрос 04-cost.sql суммирует количество продукции, делённое на выход партии, умноженное на норму и цену материала на дату заказа. Для учебных заказов получены 371,00; 126,45; 183,95. Если не хватает состава или цены, итог NULL сигнализирует о неполных данных.

Работа администратора

Для добавления нажать «Новый пользователь», заполнить логин, пароль и роль, сохранить. Для изменения выбрать строку. Пустой пароль сохраняет предыдущий; непустой формирует новый хэш. Флажок «Снять блокировку» обнуляет счётчик и снимает блокировку. Нельзя создать повторный логин или снять у себя роль администратора.

Кнопка импорта открывает диалог выбора Заказчики.json. Файл преобразуется в массив Counterparty. Метод Run до записи проверяет наличие всех семи полей исходного JSON, типы значений и уникальность id внутри файла. Некорректный файл отклоняется полностью. Полный повторный импорт обновляет совпадающие id; отсутствующие в файле записи из базы не удаляются.

Обработка ошибок и ограничения

Ожидаемые ошибки ввода показываются в окнах предупреждений. При отказе соединения предлагается проверить сервер и строку ConnectionString в Db.cs. Приложение не завершается аварийно из-за ошибки операции. SQL-параметры отделяют значения пользователя от текста команды. Таблица users имеет уникальный логин, дополнительные проверки выполняются перед сохранением.

В учебной модели одна действующая спецификация на продукт и одна базовая единица номенклатуры. API, складские остатки и несколько рецептур не реализуются. Пример проверки учебного приложения не заменяет экспертное оценивание на экзамене.
