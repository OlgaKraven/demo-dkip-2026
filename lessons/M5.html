Сделайте короткое руководство к своей работающей программе. Для каждого действия укажите, куда нажать и какой результат появится. Заполненный образец находится в «Примерах проектов».

1. Создайте документ и заголовки

  1. Создайте документ «Проектная документация — Полесье». Сохраните в папку сдачи.
  2. На первой странице укажите название системы, автора, дату и стек C# Windows Forms + {{stackLabel}}.
  3. Добавьте разделы: назначение, запуск, состав проекта, методы, руководство пользователя, руководство администратора, проверки.

Проверьте: Документ сохранён, разделы видны в оглавлении редактора.

2. Опишите назначение тремя предложениями

  1. Напишите, кому нужна система и какие данные она обрабатывает.
  2. Перечислите действия пользователя: вход, просмотр заказчиков, просмотр стоимости заказов.
  3. Перечислите действия администратора: импорт заказчиков, создание и изменение учётных записей, снятие блокировки.

Пример начала: «Система молочного комбината „Полесье“ помогает сотрудникам просматривать заказчиков и материальную стоимость заказов». Допишите только реализованные вами функции.

Проверьте: Описание совпадает с доступными окнами и кнопками приложения.

3. Запишите условия запуска

  1. Укажите Windows, .NET Framework 4.8 и выбранный сервер {{stackLabel}}.
  2. Опишите создание пустой базы и выполнение Sql/01-schema.sql, 02-customers.sql, 03-demo.sql.
  3. Укажите, где меняется подключение: исходный файл Data/Db.cs, поле ConnectionString. После изменения сохраните файл и пересоберите проект.
  4. Перечислите файлы переноса: exe, dll и содержимое выходной папки, включая Assets. Сервер базы запускается отдельно.

Не пишите, что достаточно положить Db.cs рядом с exe: программа не перечитает исходный C# без новой сборки. Учётная запись сервера базы и логин приложения — разные учётные записи.

Проверьте: Другой человек сможет подготовить базу и запустить сборку по вашему описанию.

4. Объясните состав проекта

  • UI: LoginForm — вход, MainForm — рабочие вкладки, PuzzleControl — пазл.
  • Models: классы сущностей, например User и Counterparty.
  • Data/Db.cs: подключение и выполнение команд базы.
  • Services: проверка входа, паролей, управление пользователями, импорт.
  • Sql/04-cost.sql: материальная стоимость заказов.

Проверьте: В документе перечислены файлы вашего проекта и назначение каждого блока.

6. Напишите действия пользователя

  1. Ввести логин и пароль, собрать пазл обменом двух фрагментов, нажать «Войти».
  2. Открыть «Заказчики», проверить список и нажать «Обновить».
  3. Открыть «Стоимость заказов», прочитать номер и сумму. NULL означает недостающие данные.
  4. Закрыть рабочее окно, чтобы вернуться к входу.

Рядом с каждым действием вставьте снимок своей программы и подпись: например, «Рисунок 2 — список заказчиков после обновления».

Проверьте: По инструкции можно пройти от запуска до выхода без объяснений преподавателя.

7. Напишите действия администратора

  1. Для импорта: «Заказчики» → «Импорт Заказчики.json» → выбрать файл → проверить результат.
  2. Для создания: «Пользователи» → «Новый пользователь» → логин, пароль, роль → «Сохранить».
  3. Для изменения: выбрать строку, исправить поля, сохранить. Пустой пароль сохраняет прежний.
  4. Для разблокировки: выбрать строку, отметить «Снять блокировку», сохранить и проверить повторный вход.

Проверьте: Описаны создание, изменение, разблокировка и импорт. Эти действия доступны администратору.

8. Добавьте сообщения об ошибках

  • Пустые поля — заполнить логин и пароль.
  • Неверный пароль или пазл — исправить данные; после трёх ошибок запись блокируется.
  • Повторный логин — выбрать уникальное имя.
  • Нет соединения — проверить сервер и ConnectionString, затем пересобрать при изменении.
  • Ошибка импорта — исправить JSON и повторить; часть файла не должна сохраниться.

Проверьте: Формулировки соответствуют фактическим сообщениям вашей программы.
